## How it works

One command. No config. No cloud.

1

Run npx agentopolis

It starts a tiny server on 127.0.0.1, opens the city in your browser, and — with your explicit consent — adds async, observe-only hooks to ~/.claude/settings.json. Your existing hooks are untouched, and the file is backed up first.

2

Code like you always do

Every Claude Code session appears as a worksite in a district named after its repo. Subagents walk out of the building as pixel workers, doing whatever they're actually doing — reading, editing, testing, committing.

3

Glance, don't babysit

When a session needs a permission or an answer, its building lights a pulsing beacon and a worker raises a hand. Everything else stays calm. One look at the skyline tells you who's working, who's stuck, who's done.

## Principles

Two rules the renderer never breaks.

⚑Truth before animation

Every animation is driven by a real event from Claude Code hooks. A worker only hammers while a tool call is actually running; the moment it ends, they stop. States come from a reducer over a versioned event protocol — not vibes.

Stale activities time out to idle, never to "failed". Out-of-order events are tolerated. Duplicates are dropped. If the city shows a test running, a test is running.

🌳Calm by default

No sounds, no toasts, no notification anxiety. Workers stroll at an unhurried pace, buildings twinkle slowly, and prefers-reduced-motion is honored throughout.

Attention is the only loud thing in the city — a pulsing beacon you can spot from any zoom level. When nobody needs you, the city is just a nice place to have open on a second monitor.

## Privacy is the architecture

Not a settings toggle — the way the whole thing is built.

Local only

The server binds to 127.0.0.1 and nothing else — ever. No telemetry, no analytics, no cloud, no network calls. This page has none either.

Metadata only

Redaction happens at the edge, in the hook bridge, before anything hits disk. File basenames, not contents. Sanitized command heads (secrets masked, 80-char cap), never full commands. No prompts, no assistant messages, no env values.

Open source

MIT licensed, zero runtime dependencies, small enough to actually read. The event protocol is documented; the redaction layer is one file.

One-command uninstall

npx agentopolis --uninstall removes the hooks and the bridge from your machine. Your local history lives in ~/.agentopolis — delete it any time.

## FAQ

The five questions everyone asks.

Will this slow down Claude Code?
No. The hooks are async and observe-only — they never block a tool call, a permission prompt, or your input, and they carry a 10-second timeout as a hard ceiling. If the city server isn't running, hook payloads spool to a local folder and are replayed on the next start.
What data leaves my machine?
Nothing. The server listens on 127.0.0.1 only, and there is no telemetry of any kind. What's stored locally is already-redacted metadata: session ids, tool names, file basenames, sanitized command heads. File contents, prompts, and assistant messages never reach the event stream in the first place.
Does it mess with my Claude Code settings?
Only with your consent — it asks before touching anything (or pass --yes). Hooks are merged into ~/.claude/settings.json non-destructively: existing hooks from other tools are untouched, the file is backed up before the first write, and uninstall removes only Agentopolis's own entries.
Do I lose the city when I restart?
No. Districts, permanent buildings, and geography persist in ~/.agentopolis/city.json and survive restarts. Events that fire while the server is down are spooled and replayed, so the city catches up on what it missed.
Can I try it without installing hooks?
Yes — npx agentopolis --demo runs a synthetic agent swarm and never touches your Claude settings. In fact, the background of this page is that exact demo: the shipped renderer fed by the shipped demo script, running live in your browser.
